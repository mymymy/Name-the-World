Stitch Atlas

Coastlines snapped to a grid. Every vertex is rounded to the nearest cell and consecutive duplicates are dropped, which turns a map into something closer to a needlework chart — and, because the rounding depends only on the coordinate, leaves neighbouring countries still welded along their shared borders.

How it works

  1. Project each point to screen coordinates as usual.
  2. Round both coordinates to the nearest multiple of the cell: x = Math.round(x/q)*q.
  3. If a point lands in the cell you just drew, skip it.
  4. Emit what is left as an ordinary polygon.

That is the whole trick. The reason it is worth writing down is the third line of the snippet below — the property that makes it hold together rather than fall apart.

function snappedRing(points, q, project) {
  let d = '', n = 0, px = NaN, py = NaN;
  for (const p of points) {
    let [x, y] = project(p);
    if (q) {
      x = Math.round(x / q) * q;
      y = Math.round(y / q) * q;
      if (x === px && y === py) continue;   // same cell as the last point
      px = x; py = y;
    }
    d += (n++ ? 'L' : 'M') + x + ',' + y;
  }
  return n >= 3 ? d + 'Z' : '';
}

Why the borders stay welded

Two countries hold the border between them as the same list of coordinates. Snapping is a pure function of the coordinate — not of where a point falls in a ring, nor which way round that ring is walked — so both sides round to exactly the same vertices and still meet.

Thin by index instead — keep every third point, say — and this fails badly. Each ring is walked from its own starting vertex, so each keeps a different third of the shared list, the two edges part company, and the sea shows through every seam. The grid is not just a nicer-looking decimation; it is the one that survives being applied to each shape independently.

What breaks, and the fix

A shape smaller than a cell or two falls entirely into one, leaves fewer than three distinct points, and disappears. On a world map most rings are islets, so at a large cell the majority vanish — the counter above tells you how many are in that state at the current setting.

Draw those unsnapped instead. They are a handful of points each, so it costs nothing, and an island has no neighbour to keep a seam with. Where a small shape is enclosed by another — the same boundary held twice — both copies make the same decision, because the decision depends only on the coordinates.

Two other things to leave alone: rings cut at the antimeridian, and rings drawn round a pole. Both are closed along the edge of the map, where there is no neighbour to disagree with, and the arithmetic that closes them is easier to trust unrounded.

Making it move

Fix the grid to the screen and slide the map underneath it. Vertices cross cell boundaries at different moments, so the outlines shimmer and step as they travel — stop-motion rather than a smooth glide. Nothing extra is needed: keep q in screen units rather than map units, so it is recomputed from the current scale each frame, and the effect holds its size at any zoom.

A cell of one to two pixels reads as a shimmer you notice once and then stop noticing. Past about three it becomes a pattern in its own right, which is lovely to look at and no use at all if someone is trying to read the map.
